**Step 2: Add the Intel GPU device plugin block to helm-addons.tmpl.**

Insert the Intel block immediately AFTER the NVIDIA GPU operator block (after line 961 which ends with the NVIDIA comment about "GPU Operator only manages device plugin, monitoring, and feature discovery"). The Intel block goes BEFORE the Argo Workflows section (which starts with `# ============================================================================` / `# Argo Workflows`).

Insert these exact lines:

```gotemplate

# ============================================================================
# Intel GPU Device Plugin - GPU Support for Kubernetes (Intel)
# Sync Wave: 10 (same as NVIDIA GPU operator, mutually exclusive via GPU_VENDOR)
# ============================================================================

intel-gpu-device-plugin:
  enabled: {{ eq .Values.GPU_VENDOR.Value "intel" }}
  namespace: intel-device-plugins

  chart:
    name: intel-device-plugins-gpu
    repo: https://intel.github.io/helm-charts
    version: "{{ index .Versions.Charts "intel-device-plugins-gpu" }}"
```

Key details:
- `enabled: {{ eq .Values.GPU_VENDOR.Value "intel" }}` -- renders as literal `true` when GPU_VENDOR=intel, `false` otherwise. This mirrors the NVIDIA pattern exactly (`{{ eq .Values.GPU_VENDOR.Value "nvidia" }}`).
- The block ALWAYS renders (no `{{- if }}` wrapper) -- ArgoCD needs to see the definition with `enabled: false` in the values so the Helm template gate in `intel-gpu-device-plugin.yaml` works correctly. This is the same pattern as NVIDIA.
- `{{ index .Versions.Charts "intel-device-plugins-gpu" }}` references the version key added to `versions.yaml` in Plan 01 Task 1.
- The `chart.name` and `chart.repo` fields feed into the ArgoCD Application template's `spec.source` via Helm values.
